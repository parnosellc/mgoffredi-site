~5 minutes

System User setup for Troopify

Three actions inside Business Settings, one token handoff. No advanced Meta knowledge needed.

What this is

Troopify (the ad-launching tool we're integrating) needs a non-human API identity inside your Business Manager to publish ads on your behalf. Meta calls this a System User — it's not a person (no inbox, no profile), and it can only do what you explicitly assign to it.

This is the standard way every third-party ad tool integrates with Meta. You stay in control: the System User can be revoked or its permissions changed at any time from Business Settings.

What you'll do

  1. Create a System User
  2. Assign it to ad accounts, pages, and Instagram accounts
  3. Generate a token and hand it to Michael

The steps

1

Create the System User

  1. Go to business.facebook.com
  2. Top-left, make sure you're on the correct business portfolio
  3. Open Business Settings (gear icon, or All Tools → Business Settings)
  4. Left sidebar: Users → System Users
  5. Click Add → Create new system user
  6. Name: Troopify Launcher
  7. Role: Employee (the regular System User — see note below)
  8. Click Create system user

Why Employee, not Admin? Meta hard-caps Admin System Users at 1 per Business Manager, regardless of access level — and most BMs already have theirs. Admin System Users are meant only for managing other system users, not for asset access. The Employee System User does everything Troopify needs once we assign it to the right assets in the next step.

2

Assign it to ad accounts, pages, and IG accounts

Still on the System User's page, click Add Assets (or Assign Assets). You'll see a three-panel dialog: asset type on the left, the actual assets in the middle, and permission toggles on the right. Cycle through each asset type tab on the left and configure as below.

Per-tab settings:

  • Facebook Pages — select every page you'll publish ads from. Turn Ads ON (the only required toggle). Insights is a useful add. Leave Content, Messages, Community activity, Revenue, and Leads OFF.
  • Ad accounts — select every ad account you'll launch into. Turn Manage campaigns (ads) ON. Full Control is not needed.
  • Instagram accounts — select each IG account paired with the pages above. Turn Ads and Insights ON.
  • Pixels — if your conversion pixel is listed here, assign it. If "No business assets found" appears, your pixel lives inside the ad account already and the SU inherits access through that.

Once every relevant tab has been configured, click Assign assets.

3

Generate the token

Back on the System User's page:

  1. Click Generate new token
  2. App: if prompted, select the default Meta-provided app (or accept defaults if asked to create one)
  3. Token expiration: select Never
  4. Permissions — check all three:
    ✓ads_management
    ✓pages_manage_ads
    ✓business_management
  5. Click Generate Token

Copy the token immediately. Meta only displays it once. If you lose it, you have to regenerate (which invalidates the old one).

4

Hand the token to Michael

Send the token to Michael directly in Slack. He'll pass it to Troopify, where it lives in their encrypted vault.

How to revoke at any time

  • Rotate: Business Settings → System Users → Troopify Launcher → Generate New Token (old one invalidates)
  • Full kill: Remove the System User entirely — all access dies instantly

What this can't do

The System User can only act on the assets you explicitly assigned to it. It cannot:

  • Change BM-level settings or permissions
  • Add or remove people from the BM
  • Touch any ad account or page not on its assignment list
  • Read or post organic content, DMs, or anything non-ad on the pages
  • Access your personal Facebook account or anything outside the assets you assigned

If something looks off after the integration is live, the kill switch above is one click.

Optional — how Michael verifies it works

You don't need to do this; just for transparency. A quick API ping confirms the token is alive and scoped correctly:

curl -s "https://graph.facebook.com/v19.0/me?access_token=YOUR_TOKEN"

Returns the System User's name + ID if good. Returns an error code if not — usually means a scope is missing or an asset wasn't assigned.
